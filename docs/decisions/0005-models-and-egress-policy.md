# 0005: Models, egress policy, and runtime adapters

Status: accepted (CAA-6)

## Context

Stage 6 sends source chunks to an embedding model and, later, prompts with code to a chat model. Both run in a local runtime, Ollama today. The API must be unable to send that data anywhere else, even by misconfiguration. Ollama must also be replaceable by another local runtime without touching the code that uses inference.

## Decision

- **Models.** Embeddings use `nomic-embed-text` (768 dimensions, 8192-token context, about 270 MB), which matches the `vector(768)` column. Chat uses `qwen2.5-coder:7b` (32k-token context, about 4.7 GB, roughly 8 GB of RAM or VRAM), chosen because it is tuned for code at a size that runs on a developer machine. Both are defaults of `EMBEDDING_MODEL` and `CHAT_MODEL`, so swapping a model is configuration. A different embedding model with another dimension needs a new migration and a re-index (`EMBEDDING_DIMENSIONS`). Ollama's default `num_ctx` is smaller than the models' maximum; raise it when chat prompts carry many chunks.
- **One egress path.** `PrivacyModule` provides `EgressHttpClient`, the only code allowed to open a connection. ESLint rejects the global `fetch` and imports of `node:http`, `node:https`, `undici`, and `axios` elsewhere in `apps/api` (specs and `testing/` folders excepted). It takes relative paths only, checks that the resolved URL has the pinned origin, uses `redirect: 'error'`, and applies a timeout (a whole-request limit for JSON calls, an idle limit between chunks for streams). It knows no runtime: streamed responses come out as plain lines (`postLines`), and each adapter parses its own format (Ollama sends one JSON object per line; OpenAI-compatible servers send `data:` lines).
- **URL policy.** `INFERENCE_BASE_URL` must be `http`, carry no credentials, path, query, or fragment, and have the host `localhost`, `127.0.0.1`, or `::1`. Checks run on the WHATWG-normalized URL, so lookalikes (`localhost.evil.com`, `127.0.0.1.nip.io`), userinfo and backslash tricks, and IPv4-mapped IPv6 are rejected. `https` is rejected because Ollama serves plain `http` on loopback and a pinned IP cannot satisfy a certificate. Errors name the rule, never the URL.
- **`localhost` is pinned.** It is resolved once at startup; every address must be loopback, otherwise startup fails. The client then uses the resolved IP (IPv4 preferred), so DNS or hosts changes after startup cannot redirect traffic.
- **Fail closed.** The endpoint is built by an async provider; a violation throws `PrivacyPolicyError` and the API does not start. `main.ts` logs only its fixed message.
- **One provider registry.** `INFERENCE_PROVIDERS` has the single entry `local`, and `INFERENCE_PROVIDER` accepts only `local`. There is no remote provider code and no fallback. A hosted provider would be a separate, explicit scope change.
- **Names.** A _runtime_ is the engine that runs the models (Ollama, llama.cpp server, LM Studio, vLLM). An _adapter_ is our plug-in code for one runtime. The _provider_ is where data may go; it is a privacy setting, not a plug-in.
- **Provider and runtime are separate settings.** `INFERENCE_PROVIDER` (privacy module) decides where requests may go: loopback only. `INFERENCE_RUNTIME` (inference module) picks the adapter; only `ollama` exists. Adding a runtime never relaxes the privacy rule, and hosted APIs (for example api.openai.com) stay impossible to configure.
- **One adapter per runtime, in its own folder.** Everything about a runtime lives in `modules/inference/adapters/<runtime>/`: its adapter class, the parts it delegates to, its wire types, and its specs. Its test factories live in `libs/server/testing/src/lib/<runtime>/`. The adapter implements `InferenceRuntimeAdapter`, which combines three ports: `EMBEDDING_PORT` (`embedBatch`), `CHAT_PORT` (`complete`, `stream`), and `RUNTIME_HEALTH_PORT` (`availableModels`). Its constructor receives only `EgressHttpClient` and config, so it cannot open its own connection. Adapters translate the wire format and map errors with `toInferenceError`; they hold no batching, retry, or validation logic.
- **Plugging in.** `RUNTIME_ADAPTERS` (`inference/constants/runtime-adapters.ts`) maps each runtime id to its adapter class and is the only file outside an adapter folder that names a runtime. `InferenceModule` builds one adapter for `INFERENCE_RUNTIME` and exposes it through the three port tokens (one instance). Code outside the module injects the ports or the runtime-agnostic services. ESLint rejects importing from `adapters/` anywhere except the registry, and importing one adapter folder from another.
- **Runtime-agnostic services.** `EmbeddingsService` (module `embeddings`) owns batching (`EMBEDDING_BATCH_SIZE`), bounded retries with exponential backoff (`INFERENCE_MAX_RETRIES`; network errors, timeouts, and 5xx only), and checks that the vector count and every vector length match `EMBEDDING_DIMENSIONS`. `GenerationService` (module `generation`) is the chat entry point; prompt construction joins it in Stage 8. Chat never retries and has no fallback. `InferenceHealthService` (module `health`) builds the health report from `RUNTIME_HEALTH_PORT`.
- **Ollama adapter specifics** (`adapters/ollama/`). `OllamaAdapter` delegates to `OllamaEmbedding`, `OllamaChat`, and `OllamaModels`. Embeddings post to `/api/embed` with `truncate: false`, so input that exceeds the context fails instead of being cut silently (see decision 0004). Chat uses `/api/chat` (one JSON object per line when streaming). Model presence comes from `/api/tags` with a 3 s timeout; a name without a tag matches its `:latest` tag.
- **Errors and logs.** The privacy module raises transport errors only: `EgressUnavailableError` (`network`, `timeout`, `invalid-response`, `blocked`) and `EgressHttpError` (status only; response bodies are discarded). Adapters map them with `toInferenceError` to `InferenceUnavailableError` (adds `server-error` for 5xx and a `retryable` flag), `InferenceModelNotFoundError` (404 for a model call), or `InferenceRequestRejectedError` (other 4xx, not retried). Caller aborts pass through unchanged. The HTTP filter maps inference errors to a 503 with a fixed message. Logs hold method, path, status, and duration. Tests assert that a canary used as input never reaches a log or an error message.
- **Health.** `GET /health` adds `inference` (`provider`, `runtime`, `status`, and availability of each configured model). The response is 503 `degraded` when the runtime is unreachable or either model is missing. The address is not exposed.

## Telemetry and network access

- Nx analytics are off (`"analytics": false` in `nx.json`), and the Nx TUI is disabled.
- The API's only outbound connection is to the Ollama loopback address. No dependency of the API sends telemetry.
- Network access outside this API: `ollama pull` downloads models, and the Ollama desktop app may check for updates. Both are run by Ollama, not by this repository, and neither sends repository content.

## Consequences

- Any new outbound call must go through `EgressHttpClient`; the lint rule enforces it.
- Changing the embedding model or its dimension means a migration and a full re-index.
- An opt-in smoke test (`RUN_INFERENCE_SMOKE=true`) runs `EmbeddingsService` and `GenerationService` against the runtime configured in the environment.
- **Adding or replacing a runtime.** Create `adapters/<runtime>/` with a class implementing `InferenceRuntimeAdapter` and specs against `FakeLoopbackServer`, add its test factories in `libs/server/testing/src/lib/<runtime>/`, register the class in `RUNTIME_ADAPTERS`, and add the id to `INFERENCE_RUNTIMES` in the config library. Nothing in `embeddings`, `generation`, `health`, `privacy`, or the shared inference types changes. The planned alternative is an OpenAI-compatible adapter (`/v1/embeddings`, `/v1/chat/completions` with `data:` streaming, `/v1/models`), which covers llama.cpp server, LM Studio, vLLM, and Ollama itself. Before adopting it, confirm the runtime rejects over-long embedding input instead of truncating it.
- **Switching runtime changes three settings.** Model names belong to a runtime (`qwen2.5-coder:7b` is an Ollama tag; other runtimes name models differently), so a switch sets `INFERENCE_RUNTIME`, `EMBEDDING_MODEL`, and `CHAT_MODEL` together. A wrong name shows up as a missing model in `/health`.
- **Embeddings carry their runtime.** The same model on two runtimes can produce slightly different vectors (different builds or quantization). Stage 6 must store the embedding identity as `<runtime>/<model>` (for example `ollama/nomic-embed-text`) and re-index when it changes, so vectors from different runtimes never mix in one index.
- **One runtime serves everything.** Embeddings and chat come from the same runtime. Splitting them (for example `EMBEDDING_RUNTIME` and `CHAT_RUNTIME`) would only change `InferenceModule`, because consumers already depend on separate port tokens; it is not needed now.
- Ports are deliberately small. Runtime-specific options (`truncate`, `num_ctx`, tag naming) stay inside adapters instead of widening the ports to a lowest common denominator.
